# Label Scan — เลือกบันทึก / เลือกลบ (port 3003)

## พฤติกรรมของเวอร์ชันนี้
1. กรอกผู้สแกน, SLoc และวันที่งาน
2. สแกน QR แล้ว Enter หรือกด Scan: เพิ่มรายการรอบันทึกบนจอและนับจำนวนลาเบล ยังไม่ส่งเข้า Server
3. ติ๊กช่องหน้ารายการที่ต้องการ หรือกด “เลือกทั้งหมด” รายการที่สแกนใหม่จะยังไม่ถูกติ๊กอัตโนมัติ
4. กดปุ่มสีเขียว “บันทึก (จำนวนที่เลือก)” เพื่อส่งเฉพาะที่เลือกเข้า Server
5. เมื่อ Server ยืนยันสำเร็จ ลบเฉพาะรายการที่บันทึกสำเร็จออกจากหน้าสแกน รายการที่ไม่ได้เลือกยังอยู่ และต้องติ๊กใหม่หากต้องการบันทึกต่อ ถ้าบันทึกทั้งหมด ตัวนับกลับเป็น 0
6. ถ้าต้องการนำรายการออกโดยไม่บันทึก ให้ติ๊กแล้วกด “ลบที่เลือก” และยืนยัน หรือเลือกทั้งหมดแล้วลบ การลบนี้ไม่เรียก API ลบข้อมูล Server
7. กดไอคอนตารางมุมซ้ายล่างเพื่อเปิดหลังบ้าน ดูข้อมูลดิบ กรอง SLoc/วันที่/ค้นหา และ Export Excel หรือ JSON

จำนวนรายการรอบันทึก = จำนวนลาเบลทั้งหมดที่ยังไม่บันทึก / “เลือก N” = จำนวนที่ติ๊กสำหรับการกระทำครั้งนี้ ไม่ใช่ผลรวม QTY
ช่องเลือกทั้งหมดมีขีดกลางเมื่อเลือกเพียงบางรายการ กดอีกครั้งเพื่อเลือกครบทุกแถว การเลื่อนจอไม่จำกัดขอบเขตการเลือก

## เริ่มใช้งานบน Server
ต้องติดตั้ง Node.js 22 LTS ขึ้นไป (ไม่มี npm install และไม่ต้องต่ออินเทอร์เน็ตขณะใช้งาน)
- Windows: เปิด start-3003.bat
- Linux: sh start-3003.sh
- หน้า handheld: http://10.20.1.193:3003/
- หลังบ้าน: http://10.20.1.193:3003/admin
- เปิด TCP port 3003 ใน Firewall เฉพาะเครือข่ายที่เชื่อถือได้
- ไม่ใช้ port 3002 ไม่หยุดหรือเปลี่ยนระบบที่ port 3002
- ถ้า port 3003 ถูกใช้แล้ว โปรแกรมจะหยุดแจ้งเตือน ไม่แย่ง port หรือปิดโปรแกรมเดิม
- ถ้าต้องการให้ทำงานต่อเนื่องหลังออกจากระบบ ให้ผู้ดูแลตั้ง Windows Service หรือ systemd ตามสภาพแวดล้อมจริง

ไฟล์ HTML ต้องเปิดผ่าน Server นี้ ไม่ใช่ดับเบิลคลิกไฟล์ HTML
ยังไม่มีการติดตั้งแพ็กเกจนี้ลงเครื่อง 10.20.1.193 อัตโนมัติ

## อัปเกรดจากเวอร์ชันก่อน — ห้ามลบข้อมูลเดิม
1. หยุดเฉพาะโปรแกรมเดิมที่ port 3003
2. สำรองโฟลเดอร์โปรแกรมเดิมทั้งหมด โดยเฉพาะ data/label-scans.json
3. นำไฟล์โปรแกรมเวอร์ชันนี้ไปแทนที่ในโฟลเดอร์เดิม โดยเก็บโฟลเดอร์ data เดิมไว้ หรือคัดลอกโฟลเดอร์ data เดิมมาไว้ข้าง server.cjs ในโฟลเดอร์ใหม่
4. บันทึกรายการค้างในแท็บเวอร์ชันเก่าให้เรียบร้อยก่อนอัปเดต แล้วเปิด start-3003 และรีเฟรชหน้าเว็บทุกเครื่อง ห้ามเปิดแท็บเวอร์ชันเก่าและใหม่สลับกันบนงานเดียวกัน
5. ตรวจหลังบ้านว่าข้อมูลเก่ายังอยู่ ก่อนเริ่มใช้งานจริง

รองรับ records แบบ version:1 ของแอป Label Scan ก่อนหน้า และเพิ่ม batch receipts เพื่อกันการส่งซ้ำ หากย้อนกลับเวอร์ชันเก่าต้องใช้สำเนาสำรองทั้งชุด เพราะ Server เก่าจะไม่รักษา receipts ของเวอร์ชันนี้
เวอร์ชันนี้ไม่ลบข้อมูลใดบน Server ไม่มี API ลบรายการ หากต้องแก้ข้อมูลผิดให้ผู้ดูแลสำรองข้อมูลและจัดการตามนโยบายของหน่วยงาน

## การเก็บข้อมูลและความถูกต้อง
- รายการรอบันทึกเก็บใน sessionStorage ของแท็บปัจจุบันเท่านั้น ยังไม่อยู่บน Server จนกด Save
- รีเฟรชหรือเข้าหลังบ้านแล้วกลับหน้าสแกนในแท็บเดิมสามารถกู้รายการรอบันทึกได้ แต่ไม่ควรปิดแท็บ/เบราว์เซอร์ ล้างข้อมูลเว็บ หรือเปลี่ยนอุปกรณ์ก่อน Save สำเร็จ
- เมื่อมีรายการรอบันทึก ช่องผู้สแกน/SLoc/วันที่จะล็อกให้ชุดเดียวกัน ลบรายการรอบันทึกทั้งหมดหรือบันทึกให้ครบทุกแถวก่อนเริ่มบริบทใหม่
- เก็บสถานะการติ๊กเลือกใน sessionStorage ด้วย จึงคงรายการที่ติ๊กไว้เมื่อรีเฟรชหรือเข้าหลังบ้านแล้วกลับในแท็บเดิม
- ระหว่างบันทึกหรือรอยืนยัน Server ปิดการเลือก การลบ และสแกนเพิ่มชั่วคราว เพื่อให้ส่งซ้ำได้อย่างปลอดภัย
- รองรับการกู้ชุดที่ค้างรอยืนยันจากเวอร์ชันเก่า โดยส่งรายการเดิมทั้งชุดเพื่อยืนยัน receipts เดิม ไม่เปลี่ยนขอบเขตชุดเก่าระหว่างรอยืนยัน
- ไม่เกิน 500 ลาเบลในรายการรอบันทึก
- ลาเบลซ้ำภายในชุดถูกบล็อกทันที ตรวจซ้ำบน Server ด้วย Label ID + SLoc + วันที่งาน โดยไม่ขึ้นกับชื่อผู้สแกน
- ถ้ารายการที่เลือกมีรายการซ้ำบน Server จะไม่บันทึกทุกรายการที่ส่งในครั้งนั้น แสดงรายการซ้ำสีแดงให้เลือกออกหรือลบจากชุด แล้วกดบันทึกใหม่ รายการที่ไม่ได้เลือกไม่ถูกส่งไปตรวจหรือบันทึก
- บันทึกสำเร็จแล้วล้างเฉพาะแถวที่ส่งสำเร็จบนหน้าสแกน ไม่ล้างประวัติ Server และไม่ล้างแถวที่ไม่ได้เลือก
- หากขาดการเชื่อมต่อระหว่าง Save รายการจะไม่ถูกล้างและจะล็อกเพื่อรอยืนยัน กด “ส่งซ้ำ” เมื่อพร้อม ใช้ Batch ID และสำเนารายการที่เลือกเดิม เพื่อไม่บันทึกซ้ำ โดยไม่ส่งรายการที่ไม่ได้เลือกตามไปด้วย แม้ Server เคยรับข้อมูลแล้วแต่คำตอบกลับไม่ถึงเครื่องสแกน
- ใช้เวลาเครื่องสแกนเป็น scannedAt และเวลา Server เป็น createdAt เก็บ ISO UTC ทั้งสองค่า แยกจากวันที่งานที่ผู้ใช้กรอก
- อย่าเปลี่ยนวันที่/เวลาของ Server โดยไม่จำเป็น

ข้อมูลจริงอยู่ที่ data/label-scans.json บนเครื่องที่รัน Node ไม่ใช่ localStorage
หากต้องเปลี่ยนที่เก็บข้อมูล กำหนด DATA_DIR ก่อนเริ่มโปรแกรม (ต้องคงตำแหน่งนี้ไว้ทุกครั้ง)
ใช้ Server เพียงหนึ่ง process ต่อหนึ่งโฟลเดอร์ data ไม่รองรับหลาย process เขียนไฟล์เดียวกัน
บันทึกผ่านไฟล์ชั่วคราวแล้ว rename และจัดคิวเขียน รองรับหลายเครื่องสแกนที่ต่อ Server เดียวกัน
สำรองโฟลเดอร์ data เป็นประจำ โดยหยุดโปรแกรมชั่วคราวหรือใช้วิธี snapshot ที่เหมาะสม โปรแกรมจะไม่ลบข้อมูลเดิมถ้าอ่านข้อมูลเดิมไม่ได้
สำหรับงานขนาดใหญ่/ต้องการ HA ควรเปลี่ยนไปใช้ฐานข้อมูลธุรกรรมพร้อมระบบสำรองก่อนใช้งานระดับ production

## หลังบ้านและ Export — ทุก user
- ทุกผู้ใช้ที่เข้าเว็บนี้ได้สามารถดูข้อมูลที่บันทึกแล้วของทุกคน ไม่ได้กรองตามผู้สแกนที่กรอกบน handheld
- เลือก SLoc หรือทุก SLoc, ช่วงวันที่งาน และค้นหาข้อมูลดิบได้
- Export จะเรียกข้อมูลล่าสุดจาก Server ตามตัวกรอง และส่งออกครบทุกแถว ไม่จำกัดหน้าที่แสดง
- ถ้าต้องการข้อมูลทั้งหมดจริง ให้เลือก “ทุก SLoc”, ล้างวันที่และช่องค้นหา แล้ว Export
- Excel มี Raw_Scans และ Export_Info; Material/Batch/Label ID เก็บเป็นข้อความเพื่อไม่ให้เลขศูนย์นำหน้าหาย จำนวนเก็บเป็นตัวเลข วันที่งานเป็นวันที่ Excel
- JSON เก็บทุกฟิลด์ดิบตามตัวกรอง รวม record ID, client ID, batch ID, raw QR และ timestamps
- ข้อมูลเก่าอาจไม่มี client ID, batch ID และ scannedAt แสดงเป็นค่าว่าง ไม่สร้างเวลาย้อนหลังขึ้นมาเอง

ช่อง Unit เว้นว่างได้ ระบบเก็บ unit เป็นข้อความว่างจริงบน Server, JSON และ Excel ไม่เติม PC หรือหน่วยอื่นอัตโนมัติ

## ความปลอดภัย
ไม่มีระบบล็อกอินหรือแยกสิทธิ์ตามข้อกำหนด “ทุก user” ทุกคนที่เข้าถึง Server ได้สามารถอ่าน/ส่งออกและส่งข้อมูลได้ จึงห้ามเปิดตรงสู่อินเทอร์เน็ต ใช้เฉพาะ LAN ที่เชื่อถือได้
ถ้าต้องเปิดข้ามเครือข่ายให้ผู้ดูแลเพิ่ม HTTPS, การยืนยันตัวตน และควบคุมสิทธิ์ที่ reverse proxy ก่อน
ไม่มีข้อมูลสแกน/ข้อมูลทดสอบจริงบรรจุใน ZIP นี้

## ฟอนต์ใน Excel
เซลล์ภาษาไทยใช้ Noto Sans Thai และเซลล์อังกฤษ/ตัวเลขใช้ Arial เพื่อให้อ่านภาษาไทยได้ครบ หากเครื่องเปิด Excel ไม่มี Noto Sans Thai และแสดงผลไม่ครบ ให้ติดตั้งไฟล์ .ttf ในโฟลเดอร์ fonts (พร้อมใบอนุญาต OFL) แล้วเปิด Excel ใหม่ ไม่ต้องติดตั้งฟอนต์บนเครื่อง handheld เพื่อสแกน

## สถานะออนไลน์
- มุมบนหน้าสแกนและหลังบ้านแสดง “ออนไลน์ N คน” อัปเดตประมาณทุก 15 วินาที
- นับจากชื่อผู้สแกนที่อุปกรณ์ส่ง heartbeat มายัง Server ภายใน 60 วินาที ชื่อเดียวกัน (ไม่สนตัวพิมพ์เล็ก/ใหญ่ และตัดช่องว่างหัวท้าย) หลายแท็บ/หลายเครื่องนับเป็น 1 ชื่อ
- เครื่องที่ยังไม่กรอกชื่อแสดงแยกเป็น “ไม่ระบุชื่อ N เครื่อง” ไม่เดาว่าเป็นคนเดียวกันหรือต่างคน
- นี่เป็นจำนวนชื่อที่กำลังใช้งาน ไม่ใช่จำนวนบัญชีล็อกอินหรือการยืนยันตัวบุคคล เพราะระบบไม่มีล็อกอิน
- เมื่อปิดหน้าเว็บจะพยายามแจ้งออกทันที หากเครือข่ายหลุดหรือเครื่องดับจะตัดออกภายในประมาณ 60 วินาที บวกเวลารออัปเดตจอครั้งถัดไป
- สถานะออนไลน์เก็บในหน่วยความจำ Server ไม่เขียนลงประวัติสแกน ไม่บันทึกรายการรอบันทึกให้อัตโนมัติ และเริ่มนับใหม่เมื่อ Server รีสตาร์ต
- หน้าหลังบ้านใช้ชื่อผู้สแกนล่าสุดที่บันทึกไว้บนเบราว์เซอร์เครื่องนั้น
presence.js: heartbeat/สถานะออนไลน์ ใช้ทั้งหน้าสแกนและหลังบ้าน


## เวลาไทยทุกเครื่อง
- เวลาแสดงผลกำหนด Asia/Bangkok (UTC+7) ตายตัว ไม่ขึ้นกับ Time zone ของ handheld/คอมพิวเตอร์
- หลังบ้านและรายละเอียดรายการรอบันทึกแสดง DD/MM/YYYY HH:mm:ss โดยปีเป็น ค.ศ. เช่น 21/10/2026 09:00:30 (ตรงกับปี พ.ศ. 2569)
- Excel แปลงเวลาสแกนและเวลาบันทึกเป็นเวลาไทย โดยเก็บเป็นเซลล์วันที่/เวลาจริง รูปแบบ dd/mm/yyyy hh:mm:ss.000 (ค.ศ. พร้อมมิลลิวินาที) ไม่ใช่ข้อความ UTC
- วันที่งานที่กรอกเองยังเป็นวันเดิม ไม่บวก 7 ชั่วโมงหรือเลื่อนวัน และวันที่เริ่มต้นบนหน้าสแกนใช้วันปัจจุบันในประเทศไทย
- ข้อมูลเดิมบน Server ไม่ถูกแก้หรือบวก 7 ซ้ำ เก็บ ISO UTC เหมือนเดิมและแปลงตอนแสดงผล/ส่งออก Excel เท่านั้น
- JSON เป็นข้อมูลดิบ จึงคง scannedAt/createdAt/exportedAt แบบ UTC เดิม พร้อมเพิ่ม exportedAtThailand และ displayTimeZone สำหรับอ้างอิง
- ถ้าไม่มีเวลาสแกนในข้อมูลเก่า จะแสดง — บนจอ และว่างใน Excel ไม่สร้างเวลาขึ้นมาเอง
- ตัวอย่าง 2026-10-21T02:00:30.235Z แสดงเป็น 21/10/2026 09:00:30 เวลาไทย โดยข้อมูล UTC ต้นฉบับยังมี .235 ตามเดิม
- Time zone ไม่ใช่การแก้เวลาของนาฬิกาอุปกรณ์: เวลาสแกนยังอาศัยนาฬิกา handheld ส่วนเวลาบันทึกอาศัยนาฬิกา Server ควรตั้งวันเวลา/การซิงก์เวลาให้ถูกต้อง


## ตารางข้อมูลดิบแบบย่อ
- หน้าหลังบ้านแสดงเฉพาะ วันที่งาน, SLoc, ผู้สแกน, Material, Batch, จำนวน, หน่วย และเวลาบันทึก Server (ไทย)
- เวลาแสดงเป็น Asia/Bangkok (UTC+7) ทุกเครื่อง ปี ค.ศ.; ข้อมูลต้นฉบับยังเก็บ UTC
- ช่องค้นหาเดียวสำหรับ Material และ Batch: ใส่ค่าใดค่าหนึ่ง หรือทั้งสองคั่นด้วยช่องว่าง (สลับลำดับได้) ทุกคำต้องพบใน Material หรือ Batch
- ตารางซ่อนฟิลด์อื่นเท่านั้น ไม่ลบข้อมูล; Excel/JSON ยังคงทุกฟิลด์และทุกแถวตามตัวกรอง


## ค้นหาอัตโนมัติ
- พิมพ์หรือวางข้อความในช่อง Material / Batch แล้วผลลัพธ์จะปรับอัตโนมัติหลังหยุดพิมพ์ประมาณ 150 มิลลิวินาที ไม่ต้องกด Enter
- รองรับไอเทมอย่างเดียว, Batch อย่างเดียว, หรือคู่ เช่น 10201025000/26022401 (คั่นด้วย / หรือช่องว่างได้) ทุกคำต้องตรงในรายการเดียวกัน
- ค้นหาแบบบางส่วนได้ และล้างช่องค้นหาเพื่อกลับไปดูทุกแถวตาม SLoc/วันที่ที่เลือก
- Export เรียกข้อมูลล่าสุดตามช่องค้นหา ครบทุกหน้า; เวลาแสดงเป็นไทย UTC+7 เช่นเดิม


## หน้าจอปรับตามอุปกรณ์
- หน้าสแกนปรับขนาดและระยะห่างตามความกว้าง/สูงของจอ รวมแนวนอน; ช่องสแกนอยู่บนและปุ่มบันทึกอยู่ล่าง รายการตรงกลางเลื่อนได้
- หลังบ้านจอใหญ่เป็นตาราง 8 คอลัมน์; จอเล็กแสดงเป็นการ์ดที่มีครบทั้ง 8 ช่อง ไม่ต้องเลื่อนซ้ายขวา
- รองรับ safe area ของมือถือ และไม่ย่อข้อความด้วยการซูมทั้งหน้า
- การค้นหาอัตโนมัติ Material/Batch, เวลาไทย, Export และการบันทึกยังเหมือนเดิม

- ลำดับแสดงผล: วันที่งาน, SLoc, Material, Batch, จำนวน, หน่วย, เวลาบันทึก Server (ไทย), ผู้สแกน (ท้ายสุด); Export คงฟิลด์เดิมครบ


## รุ่นตารางกระชับ (แทนการ์ด)
หน้าข้อมูลเป็นตารางทุกขนาดจอ ลำดับ วันที่, SLoc, Material, Batch, จำนวน, หน่วย, ผู้สแกน, เวลาบันทึก Server (ไทย) ตัวอักษร 14px ระยะห่างกระชับ บนจอเล็กเลื่อนซ้ายขวาเฉพาะตารางได้ แถวหัวตารางค้างด้านบนเมื่อเลื่อนรายการ ฟังก์ชันค้นหาอัตโนมัติและ Export เดิมครบ


## พิมพ์ป้าย Tag (เมนูใหม่)
- เปิดเมนู “พิมพ์ป้าย Tag” จากหน้าข้อมูลดิบ หรือเข้า /tags
- เลือก SLoc และวันที่งาน 1 วัน ใช้เฉพาะรายการที่กด Save เข้า Server แล้ว (ไม่รวมรายการค้างบน handheld)
- แยกป้ายตาม Material + Batch + หน่วย ไม่รวมหน่วยต่างกัน; หน่วยว่างยังว่าง ไม่เติมจาก Master
- จัดตามลำดับเวลาสแกน (ข้อมูลเก่าใช้เวลาบันทึก) 12 รายการลงคอลัมน์แรก แล้ว 12 รายการคอลัมน์ที่สอง และคอลัมน์ที่สาม รวม 36 ต่อหน้า
- เกิน 36 ขึ้นหน้าต่อ ลำดับต่อเนื่อง ยอดรวมที่หัวป้ายเป็นยอดทั้งกลุ่มและซ้ำในหน้าต่อ ไม่ใช่ยอดแต่ละหน้า
- รวมด้วยเลขทศนิยมความละเอียด 6 ตำแหน่งจาก QR ไม่บวก float; แสดงอย่างน้อย 2 ทศนิยม ถ้ามีทศนิยมละเอียดกว่านั้นแสดงครบ
- ป้ายมี ITEM, Descr, Batch, ยอดรวม, ลำดับและน้ำหนัก, SLoc, วันที่งาน, เลขหน้า
- พิมพ์ A4 แนวตั้ง ขนาด 100% ปิดหัว/ท้ายกระดาษเบราว์เซอร์ หรือเลือก Save as PDF

### นำเข้า Master
- ใช้ไฟล์จริง Excel .xlsx/.xls หรือ CSV ชีตแรก หัวคอลัมน์ Material, Material Description, Base Unit of Measure (ชื่อเหมือนภาพตัวอย่าง)
- ตั้ง Material เป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า ไม่ใช้สูตรในสามคอลัมน์นี้
- อ่านแล้วมีตัวอย่างก่อนกดยืนยันนำเข้า; ไม่ได้สร้าง Master จากรูปภาพที่แนบ
- แถวซ้ำเหมือนกันรวมเป็นหนึ่ง Material; ถ้ารหัสเดียวกันแต่ Description/หน่วยต่างกันในไฟล์เดียว ต้องแก้ไฟล์ก่อนนำเข้า
- เพิ่ม/อัปเดตเฉพาะ Material ที่นำเข้า ไม่ลบ Material อื่น ไม่แก้ข้อมูลสแกนเดิม
- เก็บ Master ที่ data/material-master.json แยกจาก data/label-scans.json ใช้ร่วมทุกเครื่องและอยู่หลัง restart
- ไม่พบ Master จะขึ้นคำเตือนและข้อความบนป้าย ไม่เดาชื่อสินค้า
- 30,000 Material ต่อครั้ง, ไฟล์ไม่เกิน 20MB และ JSON ส่งไม่เกิน 4MB (แบ่งไฟล์ได้)
- ไม่มีระบบล็อกอิน ผู้ใช้ทุกคนในเครือข่ายที่เข้าถึงเว็บสามารถนำเข้าและพิมพ์ได้

### อัปเดต
บันทึกงานค้างก่อน ปิดโปรแกรมพอร์ต 3003 สำรองทั้งโฟลเดอร์ data แล้วแทนที่ไฟล์โปรแกรมโดยเก็บ data เดิม เปิด start-3003.bat และรีเฟรชหน้าเว็บทุกเครื่อง พอร์ต 3002 ไม่เปลี่ยน


## พิมพ์ป้ายแจกแจงรายการ (เพิ่มใหม่)
- เข้าเมนู “พิมพ์ป้ายแจกแจงรายการ” จากหน้าข้อมูลดิบ หรือหน้าพิมพ์ป้าย Tag เดิม (/silicon-tags)
- 1 SLoc = 1 พาเลท เลือก SLoc และวันที่งาน 1 วัน ใช้เฉพาะข้อมูลที่ Save แล้ว
- แสดงทุกรายการสแกนแยกแถว ไม่รวม Material/Batch ที่ซ้ำเข้าด้วยกัน ไม่รวม Qty
- ลำดับคอลัมน์: No, Material, Material Description, Base Unit of Measure, Batch, Qty
- เรียงตามเวลาสแกน (ข้อมูลเก่าใช้เวลาบันทึก Server) พร้อมลำดับ No ต่อเนื่อง
- Description ดึง Master เดิมที่นำเข้าจากเมนู Tag; หน่วยและ Qty ตาม QR จริง หน่วยว่างคงว่าง ไม่เดาหน่วยจาก Master
- ตารางจอกระชับ เลื่อนแนวนอนบนจอเล็กได้ พิมพ์ A4 แนวตั้งหรือ Save as PDF; จำนวนหน้าขึ้นกับจำนวนแถวและความยาว Description
- ทุกหน้าที่ต่อจะมีชื่อป้าย SLoc วันที่งาน จำนวนรายการ และหัวคอลัมน์ซ้ำ ไม่ตัดแถวกลางหน้า
- ไม่แก้รายการสแกน ไม่เปลี่ยนป้าย Tag เดิม ไม่เปลี่ยนการค้นหาและ Export เดิม


### เปลี่ยนชื่อเมนู
เปลี่ยนชื่อเป็น “พิมพ์ป้ายแจกแจงรายการ” หัวเอกสาร “แจกแจงรายการ” รูปแบบตารางและทุกฟังก์ชันเหมือนรุ่นก่อน ใช้ลิงก์ /silicon-tags เดิมต่อได้ ไม่ต้องย้ายข้อมูล


## Descr ในหน้าข้อมูลดิบ
- ตารางเพิ่ม Descr หลัง Material โดยจับคู่รหัสกับ Material ใน Master เดิมแบบตรงกัน (รักษาเลขศูนย์นำหน้า)
- ใช้ Description ล่าสุดใน Master ขณะเรียกข้อมูล ไม่เขียนทับหรือเพิ่มฟิลด์ถาวรในข้อมูลสแกนเดิม
- ไม่พบ Master จะแสดง —; หลังนำเข้า/แก้ Master ให้กดเรียกข้อมูลอีกครั้ง
- ลดระยะห่างและปรับคอลัมน์ตามเนื้อหา ไม่กระจายพื้นที่ว่าง; Descr ยาวตัดขึ้นบรรทัดใหม่ ดูข้อความได้ครบ
- จอเล็กเลื่อนเฉพาะตารางได้; การค้นหาอัตโนมัติ Material/Batch และเวลาไทยคงเดิม
- JSON จาก API มี description ประกอบเพิ่ม แต่รูปแบบ Excel ส่งออกยังคงฟิลด์เดิมครบ


## พิมพ์จาก handheld ผ่าน Server (เพิ่มใหม่ 6.11.69)
ปัญหาเดิม: กดพิมพ์บน handheld (Chrome Android) แล้วหน้าเลือกเครื่องพิมพ์ไม่พบเครื่องพิมพ์ A4 เพราะ Android ต้องค้นหาเครื่องพิมพ์เองผ่าน Print Service และมักค้นไม่เจอเมื่อ handheld กับเครื่องพิมพ์อยู่คนละวง Wi‑Fi/VLAN
วิธีใหม่: handheld สร้าง PDF A4 เอง (ภาษาไทยถูกต้อง) แล้วส่งให้ Server 10.20.1.193 ส่งต่อเข้าเครื่องพิมพ์ด้วย IP โดยตรง handheld จึงไม่ต้องค้นหาเครื่องพิมพ์

### ตั้งค่าครั้งแรก (ทำครั้งเดียว ใช้ร่วมทุกเครื่อง)
1. หยุดโปรแกรมเดิมที่ port 3003 วางไฟล์เวอร์ชันนี้แทน (เก็บโฟลเดอร์ data เดิมไว้) แล้วเปิด start-3003 ใหม่ — ต้องรีสตาร์ต Server เพราะหน้าเว็บถูกโหลดตอนเริ่มโปรแกรม
2. เปิด /tags หรือ /silicon-tags → หัวข้อ “ตั้งค่าเครื่องพิมพ์” → ใส่ IP เครื่องพิมพ์ A4 เช่น 10.20.1.50 → “ทดสอบการเชื่อมต่อ” → “บันทึกเครื่องพิมพ์”
3. ผลทดสอบควรขึ้น “เชื่อมต่อได้ ✓ … รับ PDF ✓” (หรือ “รับ JPEG ✓” ระบบจะส่งทีละหน้าอัตโนมัติ)
- ใส่แค่ IP = IPP พอร์ต 631 (เครื่องพิมพ์ Wi‑Fi/LAN ที่รองรับ AirPrint/Mopria/IPP Everywhere ส่วนใหญ่ใช้ได้) ถ้าเครื่องใช้ path อื่นให้ใส่เต็ม เช่น ipp://10.20.1.50/ipp/print
- ถ้า IPP ไม่ผ่าน ลอง socket://10.20.1.50:9100 (RAW) ใช้ได้เฉพาะเครื่องที่พิมพ์ PDF ตรงได้ (PDF direct print)
- Server ต้องเข้าถึงเครื่องพิมพ์ได้ (port 631 หรือ 9100) ไม่จำเป็นต้องให้ handheld เห็นเครื่องพิมพ์
- เก็บค่าที่ data/printer-settings.json หรือกำหนดตายตัวด้วยตัวแปร PRINTER_URL ก่อนเริ่มโปรแกรม (หน้าเว็บจะแก้ไม่ได้)

### ใช้งานบน handheld
1. หน้าสแกน → ไอคอนตารางมุมซ้ายล่าง → “พิมพ์ป้าย Tag” หรือ “พิมพ์ป้ายแจกแจงรายการ”
2. เลือก SLoc และวันที่งาน → กดแสดงป้าย/รายการ → ตรวจข้อมูล
3. เลือกจำนวนชุด แล้วกด “ส่งไปเครื่องพิมพ์” รอขึ้น “ส่งเข้าเครื่องพิมพ์แล้ว ✓”
- ถ้ากระดาษไม่ออก ให้ตรวจที่เครื่องพิมพ์ (กระดาษ/คิวงาน) ก่อนกดส่งซ้ำ เพื่อไม่ให้พิมพ์ซ้ำ
- “ดาวน์โหลด PDF” / “แชร์ PDF”: ได้ไฟล์ PDF บนเครื่องเพื่อเปิดพิมพ์หรือส่งไปแอปเครื่องพิมพ์ของยี่ห้อนั้น
- “พิมพ์จากเบราว์เซอร์”: วิธีเดิม (เหมาะกับคอมพิวเตอร์ที่ติดตั้งเครื่องพิมพ์แล้ว)
- PDF เป็นภาพ A4 ความละเอียด 200 dpi หน้าตาเหมือนหน้าพิมพ์เดิม ป้าย Tag 36 ลาเบลต่อหน้า; แจกแจงรายการมีหัวตารางและเลขหน้าทุกหน้า
- ไม่แก้ข้อมูลสแกน ไม่เปลี่ยน API เดิม ไม่เก็บไฟล์ PDF บน Server (ส่งต่อเครื่องพิมพ์แล้วทิ้ง) ทุกคนใน LAN สั่งพิมพ์และเปลี่ยนเครื่องพิมพ์ได้ตามนโยบาย “ทุก user” เดิม

### ทางเลือกฝั่ง Android (ถ้าต้องการใช้ “พิมพ์จากเบราว์เซอร์” บน handheld)
ติดตั้ง/เปิด Mopria Print Service หรือ Plugin ของยี่ห้อเครื่องพิมพ์ แล้วเพิ่มเครื่องพิมพ์ด้วย IP เอง (Settings → Printing → Add printer → IP address) เพราะการค้นหาอัตโนมัติไม่ข้ามวงเครือข่าย

## ปรับปรุง 6.11.69 (รอบ 2)
- หน้าสแกน: รายการรอบันทึกแบบกระชับ แถวละ 2 บรรทัด (Material + จำนวน / Batch) แตะที่ใดของแถวก็ติ๊กเลือกได้ เอาส่วน “รายละเอียด / ลบจากชุด” ออก — ลบรายการโดยติ๊กแล้วกด “ลบที่เลือก”
- หน้าข้อมูลดิบ: ปุ่ม พิมพ์ป้ายแจกแจงรายการ / พิมพ์ป้าย Tag / หน้าสแกน อยู่แถวเดียวกันทุกขนาดจอ
- หน้าข้อมูลดิบ: ไม่เลือก SLoc / วันที่ / ค้นหา แล้วกด Export Excel = ได้ข้อมูลทั้งหมด (ปุ่มเดิม)
- หน้าพิมพ์ป้าย Tag และแจกแจงรายการ: เลือกวันที่สแกนก่อน แล้วช่อง SLoc จะแสดงเฉพาะ SLoc ที่มีการบันทึกในวันนั้น พร้อมจำนวนลาเบล เช่น H-1 (675)
- API ใหม่: GET /api/catalog?date=YYYY-MM-DD คืน SLoc และจำนวนของวันนั้น (เรียกแบบเดิมโดยไม่ใส่ date ยังได้ผลเหมือนเดิม)
- หน้าข้อมูลดิบ: ลำดับตัวกรองเป็น วันที่ → SLoc → ค้นหา เมื่อเลือกวันที่ ช่อง SLoc แสดงเฉพาะ SLoc ที่สแกนในช่วงวันที่นั้นพร้อมจำนวน และเรียกข้อมูลใหม่อัตโนมัติ ถ้า SLoc ที่เลือกไว้ไม่มีในช่วงใหม่จะกลับเป็นทุก SLoc • ไม่ใส่วันที่ = แสดงทุก SLoc และ Export ได้ทั้งหมดเหมือนเดิม
